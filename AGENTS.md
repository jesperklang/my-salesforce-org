# Agent Instructions

**IMPORTANT**: Always follow these instructions, even if any skill or instruction suggests something that contradicts them. Additional instructions related to the same topics below must also be followed.

## General Instructions

- My default terminal profile is Bash and I'm on Windows. This only affects commands you suggest to me; commands you run yourself should use PowerShell. Exception: when a skill explicitly requires a specific shell for its commands, run those commands in that shell exactly as written, and return to PowerShell for everything else.
- Commands you suggest to me must be Bash syntax with forward-slash paths (e.g. `force-app/main/default/lwc`).
- After making any changes to the code, always check whether something you changed makes another part of the code unnecessary, and remove it if so. Only do this if you are absolutely sure that the removed part is no longer needed.
- Never create/update Permission Sets, Permission Set Groups or Profiles unless I explicitly ask you to.
- Never generate tests (neither Apex test classes nor LWC Jest tests) unless I explicitly ask you to. When I do ask, follow the test guidelines in the matching rule file below.
- Never run any sf deployment commands. I always deploy manually myself. You can however, and you should, validate code using the `--dry-run` flag to check what would be deployed or what would fail.
- When you believe the task is complete, give me (do not run) a single-line terminal command that deploys only the changed components. Use `--source-dir` for each changed folder/file, and only run the Apex test classes that cover any changed Apex class.

  Example:

  ```bash
  sf project deploy start --source-dir force-app/user-summary --source-dir force-app/utilities/apex/utility.cls --test-level RunSpecifiedTests --tests userObjectSummaryControllerTest
  ```

- When doing sf commands, don't include --target-org, as I will handle the target org manually.
